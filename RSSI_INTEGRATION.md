# Adding RSSI correctly

RSSI means **Received Signal Strength Indicator**. It is the signal strength measured by the receiving radio, usually in dBm. Values are normally negative; for example, `-50 dBm` is stronger than `-85 dBm`.

## Important limitation of the supplied dataset

[VeReMi NextGen](https://zenodo.org/records/19665762), used by this project, does not include RSSI in its message records. The project therefore never invents RSSI from position. It can train and predict without RSSI, using an availability mask. To obtain a model that genuinely uses RSSI, add measurements from the same simulation runs or from compatible vehicle radios and retrain the model.

Do not train without RSSI and then turn RSSI on only at prediction time. The program detects this mismatch and stops with an explanatory error.

## Accepted input methods

### Method 1: Put RSSI in each JSON message

Add an `rssi` or `RSSI` key to each received message:

```json
{
  "receiver_id": "veh_20",
  "sender_id": "veh_21",
  "messageID": "28110",
  "sendTime": 12590440832645,
  "rssi": -68.4,
  "sender": {"pos": [104.2, 55.8, 0.0], "spd": 13.1, "acl": 0.2, "hed": 91.0},
  "receiver": {"pos": [80.0, 54.9, 0.0]}
}
```

### Method 2: Supply a separate CSV

Create a CSV with exactly these columns:

```csv
receiver_id,message_id,rssi_dbm
veh_20,28110,-68.4
veh_20,28112,-69.1
veh_22,28110,-73.0
```

The same broadcast can have different RSSI at different receivers, which is why `receiver_id` is required.

Build the processed dataset with the measurements:

```bash
python prepare_data.py --raw-dir data/raw --output-dir data/processed --rssi-csv data/rssi.csv --overwrite
python train.py --config configs/recommended.yaml --run-dir runs/recommended-rssi
```

Use compatible receiver-side measurements during prediction:

```bash
python predict.py \
  --checkpoint runs/recommended-rssi/best_model.pt \
  --input new_messages.json \
  --rssi-csv new_rssi.csv \
  --output predictions.csv
```

## What the model learns from RSSI

The relationship branch receives:

| Feature | Meaning |
|---|---|
| `rssi_available` | Distinguishes a missing measurement from a real value. |
| `rssi_dbm` | Current received signal strength. |
| `rssi_delta` | Change from the sender's previous measurement. |
| `rssi_rolling_mean` | Short-term average signal strength. |
| `rssi_rolling_std` | Short-term signal stability. |
| `max_nearby_rssi_similarity` | Strongest RSSI similarity to another identity observed by the same receiver at nearly the same time. |

For **Sybil detection**, several identities generated by one transmitter can have unusually similar RSSI, position, speed, heading, and motion at the same receiver and time. RSSI is supporting evidence, not proof: two honest vehicles close together may also have similar signal strength.

For **Illusion detection**, the fusion layer compares RSSI behavior with claimed sender-to-receiver distance, motion, speed, acceleration, and heading. A claimed position that changes unrealistically or repeatedly disagrees with the signal trend becomes suspicious.

## Where to obtain real RSSI

- Log `receivedPower`/RSSI from the radio model if regenerating the traffic in OMNeT++, Veins, Eclipse MOSAIC, or a comparable simulator.
- Log per-packet RSSI from an IEEE 802.11p/ITS-G5 or C-V2X receiver during a field experiment.
- Keep RSSI tied to the receiver and message, in dBm, with the same IDs and timestamps as the mobility messages.

Avoid calculating “RSSI” from a simple distance formula and treating it as measured data. That leaks the same position claim into both inputs and omits fading, antenna effects, obstruction, interference, and transmitter-power variation.

## Quality checks before training

1. Confirm that dBm values are plausible, usually between roughly `-120` and `-20`.
2. Check the percentage of messages with RSSI; a tiny measured subset may not help.
3. Make sure Train, Validation, and Test measurements came from their respective official splits.
4. Never use labels or attacker identity to fill missing RSSI.
5. If hardware and simulation data are combined, report separate test results for each domain.
